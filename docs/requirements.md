# R.PHOTO Portfolio Site Requirements

## 目的

このサイトは、カメラマンとしての作品・撮影スタイル・依頼方法を分かりやすく伝え、撮影相談につなげるためのポートフォリオサイトである。

現在のサイトは演出や技術要素が前に出すぎており、訪問者が「誰が、何を撮れる人で、どう依頼すればよいのか」をすぐに理解しにくい。今後は、写真を主役にしたシンプルで信頼感のある構成へ変更する。

## 基本方針

- 写真を最優先に見せる。
- トップページの最初の画面で、代表作と撮影ジャンルが分かるようにする。
- AIや特殊演出は主役にしない。必要な場合のみ、制作補助やレタッチの文脈で控えめに扱う。
- 依頼者が迷わず問い合わせできる導線を作る。
- 作品数は多く見せすぎず、強い写真だけに絞る。
- 画像は軽量化し、スマートフォンでも速く表示されるようにする。
- 日本語の文字化けを解消し、SEOやSNS共有時の表示も整える。

## 想定ユーザー

### 個人の依頼者

- プロフィール写真を撮りたい人
- SNS、宣材、アーティスト写真を必要としている人
- 記念日やイベントの撮影を相談したい人

### 法人・店舗の依頼者

- 店舗、商品、サービスの写真が必要な事業者
- WebサイトやSNS用のビジュアル素材を作りたい事業者
- イベント、採用、広報用の撮影を依頼したい企業

### 作品を見る人

- 写真家としての作風を知りたい人
- 展示、コラボ、制作依頼を検討している人
- Instagramなどから流入した人

## サイト全体の構成

推奨するナビゲーションは以下。

```text
Home / Works / Services / About / Contact
```

現在の `News` は優先度を下げる。継続的に更新する明確な目的ができるまでは、トップナビから外す。

現在の `AI Photographer` はトップナビから外す。写真家としての信頼形成を妨げないよう、必要であればAboutまたはServices内の補足として扱う。

## Home

### 役割

訪問者に対して、数秒で以下を伝える。

- R.PHOTOがカメラマンであること
- どのジャンルを撮影できるか
- 作品を見るか、撮影を相談できること

### ファーストビュー

代表作を背景にしたヒーロー、または代表作4枚程度のグリッドを表示する。

現在のような外部ストック画像は使用しない。必ず本人の作品を使う。

### 表示テキスト案

```text
R.PHOTO
Photographer based in Tokyo
Portrait / Landscape / Aerial / Commercial
```

日本語版の説明文:

```text
東京を拠点に、人物・風景・店舗・空撮まで対応するフォトグラファー。
地上と空から、印象に残るビジュアルを制作します。
```

### CTA

ファーストビューには以下の2つを置く。

```text
Worksを見る
撮影を相談する
```

`Worksを見る` は作品一覧へ移動する。  
`撮影を相談する` はContactへ移動する。

### Homeのセクション構成

1. Hero
2. Selected Works
3. Services
4. About Preview
5. Shooting Flow
6. Contact CTA

### Selected Works

トップページでは12枚程度に絞る。

目的は「たくさん見せる」ことではなく、「この人に頼むとこういう写真が撮れる」と一瞬で伝えること。

表示する写真のバランス案:

- Portrait: 3枚
- Landscape / Nature: 3枚
- Aerial / Drone: 3枚
- Commercial / Event: 3枚

## Works

### 役割

写真家としての実力と作風を見せる中心ページ。

### カテゴリ

推奨カテゴリは以下。

```text
All
Portrait
Landscape
Aerial
Commercial
Event
```

現在の `Cityscape` や `Nature` は悪くないが、依頼者目線ではやや抽象的。依頼につなげるなら、`Aerial`、`Commercial`、`Event` のような分かりやすいカテゴリ名を優先する。

### 表示件数

- 全体で30枚前後
- 各カテゴリは10から20枚程度
- トップページには12枚程度

すべての写真を並べるのではなく、作品として強いもの、今後依頼されたいジャンルのものだけを残す。

### 各作品の情報

モーダルまたは詳細表示では、必要に応じて以下を表示する。

- タイトル
- カテゴリ
- 撮影地
- 撮影年
- 用途または撮影意図
- 使用カメラは任意

機材情報は依頼者にとって優先度が低いため、前面には出さない。

### 作品ページの注意点

- ホバー演出は控えめにする。
- 写真の上に濃いグラデーションや大きな文字を重ねすぎない。
- クリックしなくても写真の魅力が伝わるレイアウトにする。
- スマートフォンでは1列、タブレットでは2列、PCでは3列程度を基本にする。

## Services

### 役割

何を依頼できるのか、依頼者に分かりやすく伝える。

### サービス分類案

#### Portrait

プロフィール写真、宣材写真、SNSアイコン、アーティスト写真など。

表示内容:

- 自然光またはロケーション撮影
- SNS、Web、名刺、プロフィール用途
- 個人、アーティスト、クリエイター向け

#### Commercial

店舗、商品、サービス、Webサイト、SNS用素材など。

表示内容:

- 店舗撮影
- 商品・サービス撮影
- ブランドイメージ撮影
- SNS、Web、広告素材

#### Event

イベント、ライブ、展示、企業行事、記念日など。

表示内容:

- 当日の雰囲気を記録
- 人物、会場、ディテールを撮影
- Web掲載や記録用に納品

#### Aerial / Drone

空撮に対応する場合の専用カテゴリ。

表示内容:

- 風景、建築、施設、観光、プロモーション向け
- 地上撮影と組み合わせたビジュアル制作
- 法令、許可、安全確認が必要であることを明記

### 料金表示

料金は詳細に決めきれない場合でも、目安を表示する。

例:

```text
Portrait: 30,000円から
Event: 50,000円から
Commercial: 要相談
Aerial / Drone: 要相談
```

価格を出したくない場合でも、`撮影内容に応じてお見積もりします` だけでは弱い。依頼者が問い合わせ前に不安にならないよう、最低価格または相談可能な範囲を示す。

## About

### 役割

写真家としての人物像と、依頼して大丈夫だと思える安心感を伝える。

### Aboutに含める内容

- 名前または活動名
- 拠点
- 撮影ジャンル
- 撮影スタイル
- 対応エリア
- 問い合わせ先
- InstagramなどのSNS

### 文章量

100から200字程度を基本にする。

長すぎる思想文や機材紹介は避ける。依頼者が知りたいのは、主に「何を撮れる人か」「どんな姿勢で撮る人か」「どこで依頼できるか」である。

### About文案

```text
R.PHOTOは東京を拠点に活動するフォトグラファーです。
人物、風景、店舗、イベント、空撮など、地上と空の両方から印象に残るビジュアルを制作しています。
自然な表情や場所の空気感を大切にし、用途に合わせた撮影をご提案します。
```

## Shooting Flow

依頼の流れをHomeまたはServicesに掲載する。

```text
1. お問い合わせ
2. 内容確認・お見積もり
3. 撮影日程の調整
4. 撮影
5. セレクト・レタッチ
6. オンライン納品
```

依頼者が不安になりやすい点を先回りして説明する。

- 納期目安
- レタッチの有無
- 納品方法
- 雨天時の対応
- 出張対応

## デザイン方針

### 全体

- 写真を主役にする。
- 装飾は少なくする。
- 余白を使い、ギャラリーのように見せる。
- 文字は読みやすく、情報量を絞る。
- アニメーションは控えめにする。

### カラー

推奨:

- 背景: 白、黒、またはごく淡いグレー
- 文字: 黒、白、グレー
- アクセント: 1色のみ

避ける:

- 強いネオングリーン
- 紫や青の派手なグラデーション
- オーロラ、粒子、SF風の演出

### タイポグラフィ

- 見出しは大きくしすぎない。
- 写真を邪魔しない細めの書体を使う。
- 日本語と英語が混在しても読みやすいサイズにする。

### 写真レイアウト

候補:

- Heroに大きな代表作1枚
- Heroに2x2の代表作グリッド
- Worksはmasonryまたは整列グリッド
- 作品詳細はライトボックスまたはモーダル

## デザイン具体案・ワイヤーフレーム

### 推奨デザインコンセプト

```text
Gallery First / Quiet Editorial
```

写真を最初に見せ、UIはできるだけ静かにする。  
写真集、ギャラリー、撮影事務所のWebサイトの中間くらいの印象を目指す。

キーワード:

- 余白
- 大きな写真
- 短い言葉
- 明確な問い合わせ導線
- 派手な演出ではなく、写真の説得力

### デザイン方向性

推奨はA案。

```text
A案: Full-Bleed Hero
代表作1枚を大きく見せる。最も写真家らしく、第一印象が強い。

B案: Editorial Grid
代表作4から6枚をグリッドで見せる。撮影ジャンルの幅を伝えやすい。

C案: Minimal Index
白背景に写真サムネイルを並べる。作品集らしいが、商用依頼の導線は弱くなりやすい。
```

このサイトでは、依頼につなげる目的があるため、`A案: Full-Bleed Hero` を基本にし、トップ下部の `Selected Works` でグリッド表現を使う。

### 色と質感

推奨カラーパレット:

```text
Base Light: #F7F5F0
Base Dark : #111111
Text      : #1A1A1A
Muted     : #7A7A72
Line      : #D8D4CC
Accent    : #8A6F45
```

使い方:

- 基本は白または淡いグレー背景。
- Works詳細やヒーローのみ黒背景を使ってもよい。
- アクセント色はボタン、リンク、カテゴリ表示に限定する。
- 写真自体の色を邪魔しない。

### 余白とサイズ

```text
Page max width : 1120pxから1280px
Section padding desktop : 96px 24px
Section padding mobile  : 64px 20px
Grid gap desktop        : 24px
Grid gap mobile         : 16px
Border radius           : 0pxから8px
```

角丸や影は控えめにする。  
写真をカード風に囲いすぎず、ギャラリーの壁に並べるような見え方を優先する。

### 使わないデザイン

以下は避ける。

- ネオン風グラデーション背景
- オーロラや粒子が常時動く背景
- 大量のアイコン
- ホバーしないと写真が見えないUI
- 文章をカードに詰め込んだトップページ
- 写真よりも大きい装飾見出し
- 複雑な横スクロール
 
### 参考にする見え方

```text
トップ: 大きな写真 + 短い肩書き
作品: 余白のあるグリッド
サービス: 4分類で明快
About: 短いプロフィール
```

## 技術要件

### 画像最適化

現在の写真ファイルは大きく、読み込み速度に影響している。公開用には軽量化した画像を使う。

目安:

- Hero画像: 300KBから800KB程度
- サムネイル: 100KBから300KB程度
- 詳細表示用: 800KBから1.5MB程度

対応方針:

- WebPまたはAVIFを検討する。
- 必要以上に大きい元画像をそのまま配信しない。
- `loading="lazy"` を使う。
- ファーストビュー画像は優先読み込みを検討する。

### Vite / GitHub Pages

- `npm run build` で生成される `dist` のみをGitHub Pagesへ公開する。
- `vite.config.ts` の `base` は `/my-portfolio/` を維持する。
- GitHub Actionsでbuildとdeployを行う。

### SEO / メタ情報

`index.html` の文字化けを解消する。

必要なメタ情報:

- title
- description
- og:title
- og:description
- og:image
- og:url
- lang="ja"

title案:

```text
R.PHOTO | 東京のフォトグラファー
```

description案:

```text
東京を拠点に、人物・風景・店舗・イベント・空撮に対応するフォトグラファー R.PHOTO のポートフォリオサイトです。
```

- 粒子背景

訪問者がトップページを開いた瞬間に、強い写真が見える。

その上で、以下がすぐに分かる状態を目指す。

```text
この人は東京拠点のフォトグラファーである。
```
